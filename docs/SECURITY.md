# Документация по безопасности P2P File Share

Этот документ описывает меры безопасности, реализованные в системе.

## Обзор

P2P File Share разработан с учетом безопасности. Основные принципы включают: передачу данных по зашифрованным каналам, минимизацию времени хранения файлов на сервере и защиту от несанкционированного доступа.

## Ключевые меры безопасности

### 1. Шифрование транспорта (TLS/SSL)

*   **HTTPS для веб-интерфейса:** Все соединения с веб-сервером (Nginx) осуществляются по протоколу HTTPS. Это гарантирует, что:
    *   Весь трафик между клиентом и сервером (HTML, JS, сигнальные сообщения) зашифрован.
    *   Предотвращается атака "человек посередине" (MITM) на этапе сигнализации.
*   **TLS для TURN-сервера:** Сервер Coturn настроен на использование TLS (порт 5349), что обеспечивает шифрование данных, передаваемых через ретранслятор, если прямое P2P-соединение невозможно.

### 2. Управление жизненным циклом файлов

*   **Одноразовые ссылки:** Каждый загруженный файл получает уникальный идентификатор (ID). По этому ID можно скачать файл только один раз.
*   **Автоматическое удаление:** Файл удаляется с сервера сразу после того, как он был успешно скачан.
*   **Ограничение времени хранения:** Если файл не был скачан в течение одного часа после загрузки, он автоматически удаляется. Это предотвращает накопление данных на сервере.

### 3. Аутентификация и авторизация

*   **Аутентификация TURN-сервера:** Coturn настроен на использование механизма `use-auth-secret` с секретом, заданным в переменной окружения `TURN_SECRET`. Это предотвращает несанкционированное использование TURN-сервера третьими лицами, что могло бы привести к злоупотреблению пропускной способностью.
*   **Секреты в переменных окружения:** Критически важные данные, такие как `SECRET_KEY` (для Flask) и `TURN_SECRET`, хранятся в файле `.env`, который не включается в систему контроля версий (`.gitignore`). Это снижает риск утечки секретов.

### 4. Защита от атак

*   **Ограничение скорости (Rate Limiting):** В конфигурации Nginx (`web/nginx.conf`) настроена зона ограничения запросов `limit_req_zone`. Она применяется к ключевым эндпоинтам (`/socket.io/`, `/`, `/d/`), что помогает защитить сервер от атак типа DoS (Denial of Service) и брутфорса.
*   **Ограничение размера тела запроса:** Nginx настроен на `client_max_body_size 100M`, что ограничивает размер загружаемых файлов и предотвращает переполнение диска.
*   **Нормализация имен файлов:** Сервер нормализует имена файлов, полученных от клиента, чтобы предотвратить атаки типа Path Traversal (например, попытки доступа к `../../../etc/passwd`).

### 5. Безопасность WebRTC

*   **P2P-передача:** Основная передача файлов происходит напрямую между браузерами пользователей через зашифрованный канал WebRTC DataChannel. Сервер не участвует в передаче самих данных файла, что минимизирует его поверхность атаки.
*   **Сигнализация через защищенный канал:** Обмен сигнальными сообщениями (SDP, ICE) происходит через зашифрованный WebSocket-канал (wss://), проксируемый Nginx.

## Рекомендации по безопасности

1.  **Регулярно обновляйте зависимости:** Убедитесь, что все Docker-образы (Flask, Nginx, Coturn) и Python-пакеты обновлены до последних версий для устранения известных уязвимостей.
2.  **Используйте надежные секреты:** Сгенерируйте криптографически стойкие значения для `SECRET_KEY` и `TURN_SECRET` с помощью команды `openssl rand -hex 32`.
3.  **Ограничьте доступ к портам:** Убедитесь, что на сервере открыты только необходимые порты (80, 443, 3478, 5349) и что фаервол настроен соответствующим образом.
4.  **Мониторинг логов:** Регулярно проверяйте логи (`docker-compose logs`) на предмет подозрительной активности.
