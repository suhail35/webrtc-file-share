# План: Реализация полного тестирования для P2P File Share

## Обновлено: Исправление импортов

## Цель

Реализовать полный набор автоматизированных тестов для проекта `webrtc-file-share`, обеспечив высокий уровень покрытия кода и проверку ключевых сценариев работы приложения.

## Контекст

1.  **Текущее состояние:** Проект не содержит тестов. Директории `tests`, `test`, или аналогичные отсутствуют.
2.  **Инструменты:** В файле `signaling/requirements-dev.txt` явно указан `pytest==7.4.0` и `pytest-cov==4.1.0`, что подтверждает выбор pytest в качестве фреймворка для тестирования.
3.  **Структура проекта:** Основная логика приложения сосредоточена в `signaling/server.py`. Согласно ответу пользователя, тесты должны быть размещены в директории `signaling/tests/`.

## Требования

*   **Покрытие:** Полное покрытие API, логики WebRTC сигнализации и обработки ошибок.
*   **Фреймворк:** Использовать `pytest`.
*   **Размещение:** Создать директорию `signaling/tests/` и разместить все тесты там.
*   **Зависимости:** Убедиться, что `pytest` и `pytest-cov` установлены в окружении.
*   **Запуск:** Обеспечить возможность запуска тестов командой `pytest` из корня проекта или из директории `signaling/`.

## План реализации

### Этап 1: Подготовка

1.  **Создать директорию для тестов:**
    *   Создать директорию `signaling/tests/`.
    *   Создать пустой файл `signaling/tests/__init__.py`, чтобы сделать директорию пакетом Python.

### Этап 2: Написание тестов

Написать следующие модули тестов в директории `signaling/tests/`:

1.  **`test_api_endpoints.py`:**
    *   Тесты для `GET /health` (ожидается 200 OK).
    *   Тесты для `PUT /` и `PUT /<filename>`:
        *   Успешная загрузка файла с именем в URL.
        *   Успешная загрузка файла с именем в заголовке `X-Filename`.
        *   Загрузка файла без имени (должно использоваться имя по умолчанию `file.bin`).
        *   Проверка формата ответа (содержит ссылку и команду curl).
    *   Тесты для `GET /d/<file_id>`:
        *   Успешное скачивание существующего файла.
        *   Поведение при запросе несуществующего `file_id` (404 Not Found).
        *   Проверка, что файл удаляется после скачивания (второй запрос должен вернуть 404).
        *   Проверка обработки заголовка `User-Agent` для `curl`.

2.  **`test_webrtc_signaling.py`:**
    *   Тесты для обработки событий Socket.IO:
        *   `create_room`: Проверка создания комнаты, генерации `roomId`, присоединения к комнате.
        *   `join_room`: Проверка успешного присоединения получателя, обработки ошибок (комната не существует, комната занята, отправитель пытается присоединиться).
        *   `offer`, `answer`, `ice_candidate`: Проверка ретрансляции сообщений в правильную комнату.
    *   Тесты для обработки отключений (`disconnect`):
        *   Поведение при отключении отправителя (комната закрывается).
        *   Поведение при отключении получателя (комната остается, получатель сбрасывается).

3.  **`test_file_utils.py`:**
    *   Тесты для функции `normalize_filename`:
        *   Обработка URL-кодированных имен (например, `%D1%84%D0%B0%D0%B9%D0%BB.txt`).
        *   Нормализация Unicode (NFC).
        *   Защита от Path Traversal (например, `../../etc/passwd`).
        *   Обработка имен с пробелами и специальными символами.

4.  **`test_cleanup.py`:**
    *   Тест для эндпоинта `POST /cleanup`:
        *   Проверка удаления файлов, старше 1 часа.
        *   Проверка, что файлы младше 1 часа не удаляются.

### Этап 3: Настройка и запуск

1.  **Настроить pytest:**
    *   Убедиться, что в `signaling/requirements-dev.txt` есть все необходимые зависимости.
    *   Создать файл `pytest.ini` в корне проекта для конфигурации pytest (если необходимо).
2.  **Запустить тесты и проверить покрытие:**
    *   Выполнить команду `pytest --cov=signaling --cov-report=html` из корня проекта.
    *   Проверить отчет о покрытии кода в директории `htmlcov/`.
    *   Убедиться, что все тесты проходят успешно.

## Критические файлы

*   `signaling/server.py` (основной файл для тестирования)
*   `signaling/tests/` (новая директория)
*   `signaling/requirements-dev.txt` (для проверки зависимостей)

## Верификация

1.  Все тесты должны проходить без ошибок.
2.  Отчет о покрытии кода должен показывать высокий процент покрытия (цель > 90%) для `signaling/server.py`.
3.  Должна быть возможность запустить тесты командой `pytest` из директории `signaling/`.
4.  Структура проекта должна включать новую директорию `signaling/tests/` со всеми созданными тестовыми модулями.
