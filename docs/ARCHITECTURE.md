# Архитектура P2P File Share

Этот документ описывает архитектуру и компоненты системы обмена файлами на основе WebRTC.

## Обзор

P2P File Share — это веб-приложение, позволяющее пользователям обмениваться файлами напрямую (peer-to-peer) через браузер или с помощью команды `curl`. Основная цель — обеспечить простой, безопасный и эффективный способ передачи файлов без необходимости их хранения на центральном сервере после установки соединения.

## Ключевые компоненты

### 1. Signaling Server (`signaling/server.py`)

**Технологии:** Python, Flask, Flask-SocketIO

**Ответственность:**
- Управление сессиями WebRTC.
- Обмен сигнальными сообщениями (SDP offer/answer, ICE candidates) между пиринговыми узлами.
- Обработка HTTP-запросов от `curl` для загрузки и скачивания файлов.
- Временное хранение метаданных о файлах и комнатах в памяти.

**Ключевые функции:**
- `@socketio.on('create_room')`: Создает новую комнату для передачи файлов и генерирует уникальный ID.
- `@socketio.on('join_room')`: Позволяет получателю присоединиться к существующей комнате.
- `@app.route('/', methods=['PUT'])`: Принимает файл, загруженный через `curl`, сохраняет его и возвращает одноразовую ссылку для скачивания.
- `@app.route('/d/<file_id>')`: Отдает файл по его уникальному ID и удаляет его после скачивания.

### 2. Web-интерфейс (`web/html/`)

**Технологии:** HTML, JavaScript (WebRTC API), Bootstrap

**Ответственность:**
- Предоставление пользовательского интерфейса для отправки и получения файлов.
- Инициация и управление WebRTC-соединением на клиентской стороне.

**Ключевые файлы:**
- `index.html`: Страница отправителя. Позволяет создать комнату и выбрать файл для отправки.
- `receive.html`: Страница получателя. Позволяет ввести ID комнаты и подключиться для получения файла.
- `js/webrtc-client.js`: Основная логика клиента. Создает `RTCPeerConnection`, управляет `DataChannel`, разбивает файл на чанки и отправляет/принимает их.

### 3. TURN/STUN Сервер (`turn/turnserver.conf`)

**Технологии:** Coturn

**Ответственность:**
- Обеспечение установки P2P-соединения между клиентами, находящимися за NAT или фаерволами.
- Ретрансляция данных (TURN) в случае, если прямое соединение (P2P) невозможно.

**Ключевые настройки:**
- `external-ip=${PUBLIC_IP}`: Указывает внешний IP-адрес сервера.
- `use-auth-secret` и `static-auth-secret=${TURN_SECRET}`: Обеспечивают безопасную аутентификацию клиентов.

### 4. Веб-сервер и обратный прокси (`web/nginx.conf`)

**Технологии:** Nginx

**Ответственность:**
- Раздача статических файлов (HTML, JS, CSS).
- Проксирование WebSocket-соединений (Socket.IO) к `signaling-server`.
- Проксирование HTTP-запросов (для `curl`) к `signaling-server`.
- Обеспечение HTTPS с использованием сертификатов Let's Encrypt.
- Редирект с HTTP на HTTPS.

### 5. Система развертывания (`deploy.sh`, `docker-compose.yml`)

**Технологии:** Docker, Docker Compose, Bash

**Ответственность:**
- Автоматизация процесса развертывания приложения.
- Управление зависимостями и конфигурацией через контейнеры.
- Получение и обновление SSL-сертификатов.

**Ключевые файлы:**
- `docker-compose.yml`: Определяет сервисы (`signaling-server`, `coturn`, `web-server`), их образы, порты и переменные окружения.
- `deploy.sh`: Скрипт, который проверяет конфигурацию, останавливает старые контейнеры, получает SSL-сертификаты (если необходимо) и запускает все сервисы.

## Поток данных

### Передача через браузер
1. Отправитель открывает `index.html` и нажимает "Создать комнату".
2. Браузер отправляет запрос `create_room` на `signaling-server`.
3. `signaling-server` создает комнату и возвращает уникальный `roomId`.
4. Отправитель копирует ссылку с `roomId` и отправляет ее получателю.
5. Получатель переходит по ссылке, открывая `receive.html`.
6. Браузер получателя отправляет запрос `join_room` с `roomId` на `signaling-server`.
7. `signaling-server` уведомляет отправителя о подключении получателя.
8. Отправитель создает `RTCPeerConnection`, генерирует SDP offer и отправляет его через `signaling-server` получателю.
9. Получатель принимает offer, создает свой `RTCPeerConnection`, генерирует SDP answer и отправляет его обратно.
10. Оба клиента обмениваются ICE кандидатами для установки прямого соединения.
11. При успешном установлении соединения, файл передается напрямую через `DataChannel`.

### Передача через curl
1. Пользователь выполняет команду `curl -T file.txt https://domain/`.
2. `Nginx` проксирует запрос к `signaling-server`.
3. `signaling-server` читает тело запроса, сохраняет файл во временную директорию с уникальным именем и сохраняет метаданные (оригинальное имя, путь) в памяти.
4. Сервер возвращает URL для скачивания вида `https://domain/d/abc123`.
5. Получатель использует `curl -o file.txt https://domain/d/abc123` для скачивания.
6. `Nginx` проксирует запрос к `signaling-server`.
7. `signaling-server` находит файл по `abc123`, отправляет его и немедленно удаляет файл и метаданные из памяти.
