# Документация по развертыванию P2P File Share

Этот документ описывает процесс развертывания приложения на сервере.

## Требования

*   **Сервер:** Виртуальная машина или физический сервер с доступом в интернет.
*   **Операционная система:** Любая, поддерживающая Docker (рекомендуется Ubuntu/Debian).
*   **Сеть:**
    *   Публичный (белый) IP-адрес.
    *   Доменное имя, привязанное к этому IP-адресу (например, `station307.suhail35.ru`).
    *   Открытые порты: `80` (HTTP), `443` (HTTPS), `3478` (TURN/STUN), `5349` (TURN/TLS).
*   **ПО:**
    *   Docker
    *   Docker Compose

## Процесс развертывания

Развертывание полностью автоматизировано с помощью скрипта `deploy.sh`.

### Шаг 1: Клонирование репозитория

```bash
# Клонируйте репозиторий
git clone https://github.com/suhail35/webrtc-file-share.git

cd webrtc-file-share
```

### Шаг 2: Настройка переменных окружения

```bash
# Скопируйте пример файла конфигурации
cp .env.example .env

# Отредактируйте файл .env
nano .env
```

Заполните следующие переменные:

```bash
# Ваше доменное имя
DOMAIN=station307.suhail35.ru

# Публичный IP-адрес вашего сервера
PUBLIC_IP=123.123.123.123

# Секретный ключ для Flask (сгенерируйте с помощью: openssl rand -hex 32)
SECRET_KEY=ваш_сгенерированный_секретный_ключ

# Секрет для TURN-сервера (сгенерируйте с помощью: openssl rand -hex 32)
TURN_SECRET=ваш_сгенерированный_turn_секрет

# Имя пользователя для TURN (по желанию)
TURN_USERNAME=turnuser

# Пароль для TURN (по желанию, сгенерируйте с помощью: openssl rand -hex 16)
TURN_PASSWORD=ваш_сгенерированный_turn_пароль
```

### Шаг 3: Запуск скрипта развертывания

```bash
# Сделайте скрипт исполняемым
chmod +x deploy.sh

# Запустите скрипт
./deploy.sh
```

### Что делает скрипт `deploy.sh`

1.  **Проверка:** Проверяет наличие файла `.env` и обязательных переменных (`DOMAIN`, `PUBLIC_IP`).
2.  **Остановка:** Останавливает и удаляет старые контейнеры, если они запущены.
3.  **Получение SSL-сертификатов:** Если в директории `./web/ssl` нет сертификатов для вашего домена, скрипт автоматически запускает `certbot` для получения бесплатных сертификатов Let's Encrypt.
4.  **Создание директорий:** Создает необходимые директории для логов (`./signaling/logs`, `./turn/logs`).
5.  **Запуск контейнеров:** Запускает все сервисы (Flask, Coturn, Nginx) с помощью `docker-compose up -d --build`.
6.  **Проверка:** Проверяет статус и здоровье запущенных контейнеров.

### Шаг 4: Проверка работы

После успешного выполнения скрипта, приложение будет доступно по адресу:

`https://<ваш-домен>`

Вы можете проверить его работоспособность:

```bash
curl https://<ваш-домен>/health
```

Ожидаемый ответ: `{"status":"ok"}`.

## Управление

*   **Просмотр логов:** `docker-compose logs -f`
*   **Остановка сервисов:** `docker-compose down`
*   **Перезапуск сервисов:** `docker-compose restart`

## Обновление

Для обновления приложения до последней версии:

```bash
git pull origin main
./deploy.sh
```

Скрипт `deploy.sh` пересоберет контейнеры и перезапустит сервисы с новым кодом.
